## Behavior and safeguards

The candidate first compares the actual schema with the captured baseline:
columns/nullability, constraints, triggers, indexes, policies, RLS, table/column/
function privileges, client role memberships and storage settings. Unexpected
differences abort before changes. PostgreSQL 17/18 NOT NULL catalog differences
are normalized; column nullability remains checked independently.

It then enables safe public workshop browsing, archives only the verified retired
workshop, and applies the reviewed ownership, lifecycle, server-clock, meeting,
profile/avatar and admin contracts. Profile contact links support optional empty
values and validated HTTPS URLs. Meeting clearing retains the stricter canonical
Google Meet constraint. Historical assessment records become read-only to browser
clients, including administrators. Existing server service-role access remains.

The script uses one transaction, application-table write locks, a five-second lock
timeout and a 60-second per-statement timeout. An error rolls everything back.
Reapplication fails the baseline check. Do not remove the guard to force a release:
changed schema requires a new inspection, review and test run. New NOT VALID checks
preserve legacy rows while constraining later writes; validate legacy data separately.
The final step checks critical privileges and notifies PostgREST to reload its schema.

## Reproduce the evidence

From the repository root, using the existing installed dependencies:

```powershell
node scripts/build-release.mjs --check
node --test tests/database/release.test.mjs
npm.cmd run test:db
npm.cmd run lint
```

After intentional source edits, run `node scripts/build-release.mjs`, review the
candidate/manifest diff and rerun the relevant tests. The assembler only reads and
writes local files; it never connects to a database.
